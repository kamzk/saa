    Section 2: S3 — Simple Storage Service

    The idea

    Amazon S3 (Simple Storage Service) is object storage.

    Bucket
  ↓
Object
  ├── Data
  ├── Key
  └── Metadata

    S3 is not:

    • Block storage → EBS
    • Shared filesystem → EFS / FSx

    You normally replace an entire object rather than modify individual bytes.

    Important S3 facts

    • 99.999999999% durability
    • Bucket belongs to one Region
    • Bucket names are globally unique
    • Max object size: 5 TB
    • S3 has effectively unlimited total storage

    S3 key

    photos/2026/cat.jpg

    S3 has no traditional folders; photos/2026/ is part of the key.

    S3 static website + Route 53

    S3 can host a static website containing:

    • HTML
    • CSS
    • JavaScript
    • Images
    • Other static files

    For a custom domain, Route 53 can route traffic to the S3 website endpoint.

    Important bucket-name rule

    When routing a domain directly to an S3 bucket configured for static website hosting, the:

    S3 bucket name must exactly match the domain or subdomain being routed.

    Example:

    Domain:
example.com

Bucket:
example.com

    For a subdomain:

    Domain:
www.example.com

Bucket:
www.example.com

    This is a common SAA exam requirement.

    Typical architecture

    User
  ↓
Route 53
  ↓
A / Alias record
  ↓
S3 website endpoint
  ↓
S3 bucket

    Important Route 53 prerequisites

    For the direct S3 website-endpoint pattern:

    • A registered domain name
    • An S3 bucket configured for static website hosting
    • The bucket name matches the domain/subdomain
    • Route 53 is hosting the DNS for the domain
    • Use a Route 53 A Alias record pointing to the S3 website endpoint

    Route 53 alias records can be used for both:

    example.com
www.example.com

    The S3 bucket must match the record name used for the S3 website target.

    Region misconception

    The S3 bucket does not have to be in the same Region as the Route 53 hosted zone.

    Route 53 is a global DNS service.

    You select the S3 bucket's Region when configuring the S3 website endpoint as the alias target.

    CORS misconception

    CORS is not required simply to route Route 53 traffic to an S3 website.

    Route 53
→ DNS routing

CORS
→ Browser cross-origin access

    Do not confuse the two.

    Important HTTPS caveat

    An S3 website endpoint does not support SSL/TLS directly.

    For HTTPS, a common architecture is:

    User
  ↓ HTTPS
CloudFront
  ↓
S3

    With CloudFront, you can use a custom certificate and keep the S3 bucket behind CloudFront.

    Important distinction

    The bucket-name-must-match-domain rule applies to the direct S3 website endpoint pattern.

    It does not mean every S3 bucket behind CloudFront must have the same name as the user's domain.

    For example:

    example.com
    ↓
CloudFront
    ↓
my-company-static-assets-123

    The CloudFront distribution can use a differently named S3 bucket as its origin.

    Direct Route 53 → S3 website endpoint → bucket name matches domain

    CloudFront → S3 origin → bucket name does not need to match the public domain

    S3 storage classes

    Storage class Access pattern Retrieval Minimum storage
    S3 Standard Frequent Milliseconds None
    S3 Intelligent-Tiering Unknown / changing Milliseconds in active tiers None
    S3 Standard-IA Infrequent Milliseconds 30 days
    S3 One Zone-IA Infrequent + re-creatable Milliseconds 30 days
    S3 Glacier Instant Retrieval Rare + immediate Milliseconds 90 days
    S3 Glacier Flexible Retrieval Archive Minutes–hours 90 days
    S3 Glacier Deep Archive Very rare / long-term Hours 180 days
    Important 2026 exam note

    Minimum storage ≠ minimum lifecycle transition time.

    For example, you can configure a lifecycle transition to Standard-IA or One Zone-IA at day 7 (or even day 0), but the object still has a 30-day minimum billable duration. Leaving earlier results in a prorated charge. The same principle applies to the Glacier classes: 90/90/180 days are minimum billable durations, not necessarily a mandatory waiting period before transitioning.

    Glacier classes provide the same high durability model as S3 Standard with lower storage cost.

    3-filter method

    1. Access frequency

    Frequent
→ Standard

Unknown / unpredictable
→ Intelligent-Tiering

Infrequent
→ Standard-IA / One Zone-IA

Rare
→ Glacier

    2. Retrieval speed

    Milliseconds
→ Standard / Standard-IA / One Zone-IA / Glacier Instant

Minutes–hours
→ Glacier Flexible

Hours acceptable
→ Deep Archive

    3. Retention

    Standard-IA     → 30 days
One Zone-IA     → 30 days
Glacier Instant → 90 days
Glacier Flexible→ 90 days
Deep Archive    → 180 days

    Deleting/transitioning before the minimum duration can still incur charges for the remaining minimum period.

    S3 Standard

    Use for:

    • Frequently accessed data
    • Low-latency access
    • Predictable access

    Frequently accessed → S3 Standard

    S3 Intelligent-Tiering

    Use when access is unknown or unpredictable.

    S3 automatically moves objects between access tiers. There is a small monitoring/automation charge.

    Known access schedule
→ Lifecycle

Unknown/unpredictable access
→ Intelligent-Tiering

    S3 Standard-IA

    Use for:

    • Infrequent access
    • Immediate retrieval
    • Multi-AZ resilience

    Infrequent + immediate → Standard-IA

    S3 One Zone-IA

    Stores data in one AZ.

    Use for:

    • Infrequent access
    • Re-creatable data
    • Secondary copies

    Re-creatable / secondary copy → One Zone-IA

    Do not use it as the only copy of irreplaceable data.

    S3 Glacier Instant Retrieval

    For:

    • Rarely accessed data
    • Immediate retrieval
    • Millisecond access

    Rare + immediate retrieval → Glacier Instant Retrieval

    S3 Glacier Flexible Retrieval

    For archival data where retrieval can take minutes to hours.

    Archive + minutes/hours acceptable → Glacier Flexible Retrieval

    Retrieval options

    Retrieval Typical time Use
    Expedited 1–5 min Urgent access
    Standard 3–5 hours Normal retrieval
    Bulk 5–12 hours Large, low-cost retrieval

    Provisioned Retrieval Capacity guarantees capacity for Expedited retrievals and provides up to 300 MB/s per capacity unit.

    Under 15-minute retrieval → Expedited

    Guaranteed Expedited capacity / predictable fast retrieval → Provisioned Retrieval Capacity

    Large amount + lowest retrieval cost → Bulk

    S3 Glacier Deep Archive

    For very long-term archival:

    • Regulatory records
    • Compliance archives
    • Multi-year retention
    • Very rare access

    Lowest-cost S3 storage class; retrieval takes hours.

    Cheapest long-term archive → Deep Archive

    Lifecycle rules

    Automatically:

    • Transition objects
    • Expire/delete objects
    • Delete old versions
    • Abort incomplete multipart uploads

    Example:

    Standard
   ↓
Standard-IA
   ↓
Glacier
   ↓
Delete

    Known access schedule → S3 Lifecycle

    Versioning

    Keeps multiple object versions.

    Version 1
Version 2

    A normal delete on a versioned bucket creates a delete marker rather than immediately deleting the current version.

    Delete Marker
Version 2
Version 1

    Remove the delete marker and the object becomes visible again.

    Important

    Once Versioning is enabled, it can be suspended, but the bucket cannot return to its original unversioned state.

    Accidental overwrite/deletion protection → Versioning

    Delete marker

    With Versioning enabled:

    DELETE object
→ Delete Marker created
→ Old versions remain

    But:

    DELETE object?versionId=...
→ Specific version permanently deleted

    Important event distinction:

    Delete marker
→ s3:ObjectRemoved:DeleteMarkerCreated

Permanent deletion
→ s3:ObjectRemoved:Delete

    MFA Delete

    Adds MFA protection to certain Versioning operations.

    Useful against:

    • Permanent deletion of object versions
    • Malicious deletion
    • Accidental versioning suspension

    Require MFA before permanently deleting versions → MFA Delete

    S3 Object Lock — WORM

    WORM = Write Once, Read Many

    Object Lock prevents protected object versions from being overwritten/deleted during the protection period.

    Object Lock requires Versioning.

    S3
 ↓
Versioning
 ↓
Object Lock

    Object Lock: Governance vs Compliance

    Governance Compliance
    Normal users can delete? No No
    Authorized users can bypass? Yes No
    Strict immutability Less suitable Yes
    Admin/root bypass Possible with appropriate bypass permissions No

    Governance

    Can be bypassed with s3:BypassGovernanceRetention.

    Administrators may override → Governance

    Compliance

    Cannot be bypassed during retention, including by administrators/root.

    Nobody can bypass → Compliance

    Retention period vs Legal Hold

    Retention period

    Protect until a specific date.

    "Keep for exactly 5 years." → Retention period

    Legal Hold

    Protection remains until explicitly removed.

    Litigation / investigation / case closure → Legal Hold

    Object Lock vs Versioning

    Recover old version after accidental deletion
→ Versioning

Prevent deletion/overwrite during retention
→ Object Lock

    Object Lock and replication

    For locked-object replication:

    • Source and destination must have Object Lock enabled.
    • Retention metadata can be replicated.

    Useful for compliance copies in another bucket/Region.

    Replication

    Cross-Region Replication (CRR)

    Copies objects to another Region.

    Uses:

    • Disaster recovery
    • Compliance
    • Geographic separation
    • Lower latency
    Region A
   ↓ CRR
Region B

    Same-Region Replication (SRR)

    Copies objects to another bucket in the same Region.

    Uses:

    • Log aggregation
    • Production → test
    • Separate accounts/buckets
    • Data isolation

    Requirement

    Standard replication requires Versioning on both source and destination.

    Existing objects

    Existing objects need replication → S3 Batch Replication

    Encryption

    S3 encrypts new objects by default.

    Encryption Key management Signal
    SSE-S3 AWS Simple server-side encryption
    SSE-KMS AWS KMS Key control + audit
    SSE-C Customer Customer supplies key
    Client-side Customer Encrypt before upload

    SSE-S3

    Use for simple S3 encryption without special key-management requirements.

    SSE-KMS

    Provides:

    • Customer-managed KMS key option
    • Fine-grained permissions
    • Key controls
    • CloudTrail audit

    Need to audit encryption-key usage → SSE-KMS

    S3 Bucket Key

    Reduces KMS requests and costs for large numbers of SSE-KMS objects.

    Trade-off: less granular KMS/CloudTrail visibility.

    Too many KMS requests/cost → S3 Bucket Key

    SSE-C

    Customer supplies the key with each request. HTTPS is required.

    Customer manages key for each request → SSE-C

    Client-side encryption

    Application
 ↓ encrypt
Ciphertext
 ↓
S3

    Must encrypt before AWS receives the data → Client-side encryption

    Encryption in transit

    At rest:

    SSE-S3 / SSE-KMS / SSE-C / Client-side

    In transit:

    HTTPS / TLS

    Force HTTPS with a bucket policy denying:

    aws:SecureTransport = false

    Force HTTPS → aws:SecureTransport

    VPC Endpoint Policy for S3

    An S3 Gateway VPC Endpoint provides private VPC access to S3 without an Internet Gateway or NAT Gateway.

    A VPC endpoint policy controls what can be accessed through that specific endpoint.

    VPC
 ↓
S3 Gateway Endpoint
 ↓
Endpoint policy
 ↓
Approved S3 buckets

    Different endpoints have different policies.

    EC2 can access only specific S3 buckets through an S3 gateway endpoint → Gateway VPC Endpoint + endpoint policy

    Important distinction

    VPC endpoint policy
→ controls access THROUGH the endpoint

Bucket policy
→ controls access TO the bucket

    Bucket policies

    Resource-based policies controlling:

    • Who can access
    • Cross-account access
    • HTTPS
    • Encryption
    • IP restrictions
    • VPC endpoint restrictions

    aws:sourceVpce can restrict access to a specific VPC endpoint.

    Bucket only accessible through a specific endpoint → Bucket policy + aws:sourceVpce

    S3 Requester Pays

    Used when you share an S3 dataset with other AWS accounts and want the requester to pay the S3 request and applicable data-transfer/retrieval charges instead of the bucket owner.

    Bucket owner
→ Pays for storage

Requester
→ Pays for requests
→ Pays for applicable data transfer/retrieval charges

    Useful for:

    • Large datasets shared with other AWS accounts
    • Public/shared datasets where the owner does not want to pay access costs
    • Cross-account data downloads

    Important

    Requester Pays does not grant access by itself.

    The requester must still have permission to access the bucket, such as through:

    • IAM policies
    • Bucket policies
    • Cross-account permissions

    Requester Pays requires authenticated requests, so anonymous requests are not allowed.

    Key distinction

    Cross-account access
→ Who is allowed to access the bucket?

Requester Pays
→ Who pays for the request/download?

    You may need both when sharing data with another AWS account.

    Large S3 dataset shared with another account + requester should pay access/download costs → S3 Requester Pays

    Block Public Access

    Main protection against accidental public exposure.

    Prevent public S3 access → S3 Block Public Access

    Public S3 objects

    To make S3 objects readable by anyone on the Internet:

    Bucket policy
→ Allow s3:GetObject
→ Principal: "*"

    A public-read object ACL can also make an object public when ACLs are enabled, but modern S3 buckets usually use Bucket owner enforced, which disables ACLs.

    Important

    Bucket policy / public-read ACL
→ controls whether the object is public

CORS
→ controls whether browser JavaScript can access a cross-origin response

    So:

    All S3 objects must be publicly readable → Bucket policy or public-read ACL if ACLs are enabled

    CORS does NOT make S3 objects public.

    Small exam pattern

    Public static assets readable from the Internet → Bucket policy allowing s3:GetObject to Principal: "*"

    Public-read ACL → possible only when ACLs are enabled

    CORS → not an access-control mechanism

    Do nothing → objects are not public by default

    Presigned URLs

    Temporary access to a private S3 object without giving AWS credentials.

    Customer
 ↓
Presigned URL
 ↓
Private object

    Temporary private download → Presigned URL

    CloudFront + S3: OAC

    Origin Access Control (OAC) lets CloudFront access the S3 origin while preventing direct public S3 access.

    User
 ↓
CloudFront
 ↓
S3

    Users access content through CloudFront, not directly through S3 → OAC

    OAC is preferred over the older OAI approach.

    Important distinction

    If CloudFront uses the S3 REST API origin, the S3 bucket can remain private and its name does not need to match the public website domain.

    example.com
    ↓
CloudFront
    ↓
private bucket: company-assets-123

    Do not apply the direct S3 website-endpoint bucket-name rule to this architecture.

    S3 access logs vs CloudTrail

    S3 Server Access Logs CloudTrail data events
    Main purpose Detailed S3 request/access logging AWS API/object activity
    Typical details Requester, bucket, time, operation, referrer, response time, HTTP status/error Who performed the API action and which object/API was accessed
    Typical use Detailed S3 access/request logs Audit/security
    Destination Separate S3 bucket CloudTrail event store / delivery destination

    S3 Server Access Logs

    Detailed records of requests made to an S3 bucket, including information such as:

    • Requester
    • Bucket/object
    • Request time and operation
    • Referrer
    • Response/turnaround time
    • HTTP status/error information

    Logs should be delivered to a different bucket to avoid recursive logging.

    Detailed S3 request/access details → Server Access Logs

    Who performed an S3 object API operation → CloudTrail data events

    Exam trap: Both can log S3 activity, but Server Access Logs are the better answer when the question lists fields such as request time, referrer, turnaround time, and error code.

    S3 Performance

    S3 automatically scales to high request rates.

    Per-prefix baseline

    Operation Per prefix
    PUT / COPY / POST / DELETE ≥ 3,500 requests/sec
    GET / HEAD ≥ 5,500 requests/sec

    There is no limit on the number of prefixes in a bucket.

    What is a prefix?

    A prefix is the beginning of an S3 object key.

    photos/2026/cat.jpg

    Possible prefix:

    photos/

    Prefix = part of the object key, not a real folder.

    High request rates

    To increase aggregate request throughput:

    Multiple prefixes
      +
Parallel requests
      ↓
Higher aggregate throughput

    Example:

    1 prefix  → 5,500 GET/sec
10 prefixes → potentially 55,000 GET/sec

    Important

    S3 automatically scales, so you do not normally need to create prefixes manually. For very high request rates, distributing requests across prefixes can improve performance.

    A sudden large increase in traffic can temporarily cause:

    503 Slow Down

    → retry using exponential backoff.

    Multipart upload

    Splits large objects into parts.

    Benefits:

    • Parallel uploads
    • Better performance
    • Retry individual parts

    Limits:

    • Single PUT: 5 GB
    • Max object: 5 TB

    Upload a very large file efficiently → Multipart upload

    S3 Transfer Acceleration

    Improves long-distance uploads:

    User

    Byte-range requests

    Retrieves only part of an object.

    Useful for:

    S3 Event Notifications

    S3 Event Notifications = trigger actions when objects change.

    SQS         → queue

    Important events

    Event Meaning
    s3:ObjectCreated:* Object created
    s3:ObjectRemoved:Delete Deleted / version permanently deleted
    s3:ObjectRemoved:DeleteMarkerCreated Delete marker created
    s3:ObjectRemoved:* All removal events

    Exam patterns

    New object → s3:ObjectCreated:*

    Permanent deletion → s3:ObjectRemoved:Delete

    Delete marker → s3:ObjectRemoved:DeleteMarkerCreated

    All removals → s3:ObjectRemoved:*

    Queue processing → SQS

    Notify/fan-out → SNS

    Complex routing → EventBridge

    Trap

    DELETE on versioned bucket
→ Delete marker
→ NOT permanent deletion

DELETE specific version ID
→ Permanent deletion

    Pocket card

    Object created → ObjectCreated:*
Permanent delete → ObjectRemoved:Delete
Delete marker → ObjectRemoved:DeleteMarkerCreated
All removals → ObjectRemoved:*
Queue → SQS
Notify → SNS
Complex routing → EventBridge

    S3 Select vs Athena

    S3 Select

    Queries one object and returns only matching data.

    Part of one large CSV/JSON → S3 Select

    Athena

    Queries many S3 objects/datasets using SQL.

    Analyze many S3 files → Athena

    S3 Storage Lens

    S3 Storage Lens = account-wide and organization-wide visibility into S3 usage and activity.

    It aggregates metrics and insights across all buckets and Regions from a single dashboard.

    Use it for:

    • Storage usage and growth trends
    • Cost optimization insights
    • Data protection and configuration status (including versioning status)
    • Identifying buckets that do not meet best practices
    • Organization-wide and account-wide summaries

    Key points:

    • Works across all buckets and Regions automatically
    • Provides free default dashboard metrics plus advanced paid metrics
    • Can export metrics to an S3 bucket for analysis
    • Can be scoped to an AWS Organization (organization-level dashboard)

    Signal

    Account/org-wide S3 visibility, metrics, or configuration status (e.g., which buckets lack versioning) → S3 Storage Lens

    Important distinction

    S3 Storage Lens
→ visibility, metrics, configuration insights across buckets/Regions

CloudTrail
→ API activity audit (who did what)

IAM Access Analyzer
→ external/public access analysis

    A company must retain records until a specific date, such as five years after creation. Which Object Lock mechanism should it use? → Retention period

    A company is involved in a legal investigation and must keep certain S3 objects protected until the investigation is explicitly closed. Which Object Lock mechanism should it use? → Legal Hold

    A company needs copies of S3 objects in another AWS Region for disaster recovery if the primary Region becomes unavailable. Which feature should it use? → Cross-Region Replication (CRR)

    A company needs to automatically copy objects from a production S3 bucket to another bucket in the same AWS Region for data isolation. Which feature should it use? → Same-Region Replication (SRR)

    A company enabled S3 replication but now needs to replicate objects that were uploaded before the replication rule was created. Which feature should it use? → S3 Batch Replication

    A company needs server-side encryption for S3 objects and wants to control encryption keys and audit their use through AWS KMS. Which encryption option should it choose? → SSE-KMS

    A company has millions of SSE-KMS encrypted S3 objects and wants to reduce the number of KMS requests and associated costs. Which feature should it enable? → S3 Bucket Key

    A company wants S3 to use a customer-provided encryption key with every upload and download request. Which encryption option should it use? → SSE-C

    A company requires data to be encrypted before it ever reaches AWS. Which encryption approach should it use? → Client-side encryption

    A security team requires an S3 bucket to reject any request that is made without HTTPS. Which bucket-policy condition should be used? → aws:SecureTransport

    EC2 instances in a private subnet must access only specific S3 buckets without using an Internet Gateway or NAT Gateway. Which solution should be configured? → S3 Gateway VPC Endpoint + endpoint policy

    A company wants an S3 bucket to accept requests only when they come through a particular VPC endpoint. Which bucket-policy condition can enforce this restriction? → aws:sourceVpce

    An online survey startup has 5 TB of real estate data in an S3 bucket in us-east-1. The data must be shared with a European AWS account, and the startup wants to minimize the S3 request and applicable data-transfer/retrieval costs it pays. Anonymous access must also be disabled. Which S3 feature should it use? → S3 Requester Pays

    A company wants to share a large S3 dataset with another AWS account and wants the other account to pay for the S3 requests and applicable download/retrieval charges. What feature should it enable? → S3 Requester Pays

    A security team wants to prevent an S3 bucket and its objects from accidentally becoming publicly accessible. Which S3 feature should it enable? → S3 Block Public Access

    A company wants to make every object in an S3 bucket readable by anyone on the Internet. Which approach can grant anonymous read access to the objects? → S3 bucket policy allowing s3:GetObject to Principal: "*"

    A company serves private S3 content through CloudFront and does not want users to access the S3 bucket directly. Which CloudFront feature should it use? → Origin Access Control (OAC)

    A security team needs to determine which identity accessed a specific S3 object through API activity logs. Which AWS service should be used? → CloudTrail data events

    A company needs S3 request logging and wants the logs delivered to another bucket. Which S3 feature should it use? → S3 Server Access Logs

    A client needs to download only a portion of a very large S3 object instead of retrieving the entire object. Which feature should it use? → Byte-range request

    A company wants a Lambda function to process every newly uploaded object in an S3 bucket automatically. Which S3 mechanism should trigger the function? → S3 Event Notification

    A company needs to process S3 events through a queue so consumers can process them asynchronously. Which destination should it use? → Amazon SQS

    A company wants one S3 event to be delivered to multiple subscribers for fan-out processing. Which service is most appropriate? → Amazon SNS

    A company needs advanced filtering and routing of S3 events to different targets based on event content. Which service should it use? → Amazon EventBridge

    A company needs to retrieve only matching rows from a single large CSV object stored in S3. Which service is designed for this use case? → S3 Select

    A data team needs to run SQL queries across many CSV and Parquet files stored in S3 without managing servers. Which service should it use? → Amazon Athena

    A company needs urgent retrieval of archived S3 Glacier Flexible Retrieval data and wants retrieval in a few minutes. Which retrieval option should it choose? → Expedited Retrieval

    A company needs guaranteed capacity for Expedited Glacier retrievals rather than relying on on-demand capacity. What should it purchase? → Provisioned Retrieval Capacity

    A company needs to retrieve a very large amount of Glacier Flexible Retrieval data and wants the lowest retrieval cost, while waiting several hours is acceptable. Which retrieval option should it choose? → Bulk Retrieval

    A company has a static corporate website in an S3 bucket and a registered domain in Route 53. It wants Route 53 to route traffic directly to the S3 static website. Which prerequisite is required? → The S3 bucket name must match the domain name.

    A company wants to use example.com as the custom domain for an S3 static website hosted directly through the S3 website endpoint. What should the bucket be named? → example.com

    A company wants to host www.example.com directly from an S3 static website endpoint. What should the bucket be named? → www.example.com

    A company wants Route 53 to route example.com directly to an S3 static website. Which record type should normally be used? → A Alias record pointing to the S3 website endpoint

    A company wants to route an S3 static website through Route 53 and asks whether the Route 53 hosted zone and S3 bucket must be in the same AWS Region. What is the correct answer? → No. Route 53 is global; use the S3 bucket's Region for the S3 website endpoint.

    A company configures CORS on an S3 bucket and expects that to satisfy the prerequisite for routing a custom domain from Route 53 to the S3 website. Is CORS required? → No. CORS is for browser cross-origin access, not DNS routing.

    A company wants HTTPS for a public S3 static website using a custom domain. Can the S3 website endpoint provide HTTPS directly? → No. Put CloudFront in front of S3 and use HTTPS there.

    A company uses CloudFront in front of an S3 bucket with the public domain example.com. Must the S3 bucket itself be named example.com? → No. The bucket-name matching rule applies to the direct S3 website-endpoint pattern; a CloudFront S3 origin can use a differently named bucket.
